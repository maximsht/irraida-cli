# IRRaida CLI

IRRaida помогает подготовить инвестиционную заявку или отчётность мониторинга вместе с
вашим ИИ-агентом. Документы и черновики остаются на вашем компьютере. В фонд уходит
только собранный результат и только после вашего явного подтверждения.

Одна папка IRRaida — один проект компании. В ней в каждый момент выбран один режим:

- **Заявка** — подготовка и отправка инвестиционной заявки.
- **Мониторинг** — работа с отчётностью по портфельной компании.

Здесь публикуются готовые сборки. Исходный код закрыт.

## Статус alpha 0.2.x

Это ранний технический выпуск. Режимы `application` и `monitoring` уже создают
изолированную локальную структуру, хранят разные ключи и умеют переключаться, но
production-origin MCP для обоих контуров ещё не утверждены. Поэтому любые удалённые
операции намеренно завершаются ошибкой `track_endpoint_not_configured` без DNS- или
HTTP-запроса и без передачи ключа.

Устанавливайте alpha, чтобы проверить установку, локальную структуру и сценарий
переключения режимов. Не используйте её для подачи реальной заявки или отправки
отчётности: рабочие origin и интеграционные проверки будут добавлены в следующем
релизе.

## Установка с помощью ИИ-агента

Скопируйте текст ниже целиком и отдайте Claude Code, Codex, Cursor или другому
агенту, у которого есть доступ к терминалу.

---

**Установи мне IRRaida CLI и подготовь рабочую папку проекта.**

1. Определи мою операционную систему и установи CLI.

   macOS и Linux:

   ```sh
   curl --proto '=https' --tlsv1.2 -LsSf https://github.com/maximsht/irraida-cli/releases/latest/download/irraida-cli-installer.sh | sh
   ```

   Windows (PowerShell):

   ```powershell
   powershell -ExecutionPolicy Bypass -c "irm https://github.com/maximsht/irraida-cli/releases/latest/download/irraida-cli-installer.ps1 | iex"
   ```

2. Проверь установку командой `irraida version`. Если команда не найдена, открой
   новый терминал: установщик мог добавить путь к бинарю только для новых сессий.

3. Спроси меня, что мы делаем в этой папке: готовим заявку или сдаём мониторинговую
   отчётность. Затем создай папку проекта, назвав заодно себя — свой хост:

   ```sh
   irraida init ./моя-компания --mode application --host cursor
   # или
   irraida init ./моя-компания --mode monitoring --host claude
   ```

   Не выбирай режим сам: без `--mode` команда в неинтерактивном запуске откажет.

   `--host` — это ты: `claude` (Claude Code), `cursor` (Cursor), `codex` (Codex).
   Для Claude Code и Cursor CLI сам зарегистрирует локальный MCP-сервер в конфиге
   твоего хоста, сохранив записи других серверов и положив прежний файл рядом с `.bak`.
   Для Codex он напечатает команду `codex mcp add …`, потому что конфиг у Codex только
   глобальный. Без `--host` папка создастся, но конфиг хоста тронут не будет.

4. Объясни мне, какой ключ я должен выпустить сам:

   - для `application` — MCP-токен в Flow;
   - для `monitoring` — API-ключ в профиле Monitoring.

   Не проси меня передать ключ тебе, не клади его в файл, аргументы команды или
   историю терминала.

5. Скажи мне самому выполнить `irraida auth login` в интерактивном терминале и
   скрыто вставить ключ. CLI сохранит его только в системном хранилище секретов ОС.

6. В режиме заявки запусти `irraida status`. Сервер определит активную заявку и
   создаст её отдельную рабочую папку. Не передавай и не придумывай идентификатор
   заявки на клиенте.

7. Прочитай `CLAUDE.md` или `AGENTS.md` в корне созданного проекта. Проверь, что
   сервер зарегистрирован там, где его ищет твой хост:

   - **Claude Code** — `.mcp.json` в папке проекта;
   - **Cursor** — `.cursor/mcp.json` в корне проекта (см. раздел ниже);
   - **Codex** — конфиг только глобальный, `~/.codex/config.toml`; папку проекта Codex
     не читает. CLI туда не пишет: это файл пользователя. Вместо записи `--host codex`
     печатает готовую команду `codex mcp add …` — merge делает сам Codex. Спроси
     разрешение перед запуском: регистрация видна во всех проектах пользователя.

   Если хоста нет в списке `--host`, возьми сниппет
   `irraida init --print-mcp-snippet <папка-проекта>` и вмерджи сам.
   Глобальный `~/.cursor/` не трогает ни CLI, ни ты.

8. Перезапустись в этой же папке (в Cursor: Reload MCP или полный перезапуск IDE).
   Конфигурация MCP читается хостом при старте, поэтому без перезапуска новые
   инструменты не появятся.

## Регистрация MCP в Cursor

Cursor читает project-level конфиг **`.cursor/mcp.json`** в корне открытой папки.
Это **не** тот же файл, что `.mcp.json` для Claude Code.

Регистрация — одна команда:

```sh
irraida init . --mode <режим> --host cursor
```

CLI создаст или дополнит `.cursor/mcp.json` в корне проекта. Что он при этом
гарантирует:

- записи других MCP-серверов остаются на месте — это merge, а не перезапись;
- существовавший файл сохраняется рядом как `.cursor/mcp.json.bak` до первой правки;
- если файл не разбирается как JSON, команда останавливается с ошибкой и ничего не
  меняет;
- повторный запуск ничего не меняет и лишних копий не плодит;
- в записи только `command` и `args` — ни ключей, ни токенов, ни `env`;
- глобальный `~/.cursor/` не трогается ни при каких флагах.

Дальше перезапустите Cursor или выполните Reload MCP — конфиг MCP читается один раз при
старте. Проверьте в MCP Settings, что сервер `irraida` подключён, и вызовите tool
`whoami` (мониторинг) или `status` (заявка).

Без `.cursor/mcp.json` IRRaida в Cursor доступен только через shell (`irraida …`), а не
как MCP-tools.

## Переход с версии 0.1.x на 0.2.0

Версия `0.2.0` меняет формат рабочей папки: каждая заявка получает отдельный каталог,
а выбранный режим хранится на уровне проекта. Поэтому `irraida update apply` намеренно
не устанавливает её поверх workspace `0.1.x` — CLI не должен автоматически переносить
ваши документы, evidence и техническое состояние в новый контекст.

Чтобы перейти безопасно:

1. Остановите агента и сохраните неизменяемую копию старой папки проекта.
2. Установите актуальный CLI обычной командой из раздела выше.
3. Создайте новую пустую project-папку через `irraida init ... --mode ...`, войдите
   своим ключом и в режиме заявки выполните `irraida status`.
4. Переносите только те исходные материалы, для которых вы вправе повторить приём в
   новую заявку. Не копируйте старые `.irraida/`, evidence, custody state или package.

Старая папка остаётся read-only архивом. CLI не переименовывает, не удаляет и не
перемещает в ней данные.

## Как устроена рабочая папка

### Заявка

Сразу после `init` создаётся project workspace:

```text
моя-компания/
  .irraida/      режим и техническая ссылка на ключ; не содержит сам ключ
  .agent/        заметки и рабочая память агента
  .mcp.json      конфигурация локального MCP (при `--host claude`)
  applications/  отдельные рабочие папки заявок
```

После первой аутентифицированной команды сервер сообщает, какая заявка активна. CLI
создаёт для неё каталог вида `applications/application_<shortId>/`:

```text
applications/application_<shortId>/
  .irraida/  custody: evidence, хэши, context и audit log этой заявки
  sources/   документы, которые вы предоставили для этой заявки
  work/      черновики агента
  stages/    промежуточные результаты этапов
  package/   собранный пакет — то, что может быть отправлено в фонд
```

Заявки не смешиваются: материалы, evidence и package одной заявки не попадают в
соседний `application_<shortId>`. Если сервер переключит активную заявку, предыдущая
папка останется неизменной.

### Мониторинг

Мониторинговые периоды не затирают друг друга:

```text
моя-компания/
  reports/
    01.07.2026/
      materials/   материалы периода, которые кладёте вы
      work/        черновики агента
      report/      то, что уйдёт в фонд за этот период
    01.10.2026/
      ...
```

`report/` отделён от `work/`, чтобы перед подтверждением вы видели ровно то, что
уходит на сервер.

## Основные команды

```sh
irraida status                         # текущий статус и активная заявка
irraida next                           # следующий рекомендуемый шаг
irraida how-to                         # инструкция к текущему шагу
irraida accept <step> --files <files>  # принять источники с хэшами и evidence
irraida validate                       # проверить собранный пакет
irraida submit --approve               # отправить после подтверждения человека
```

Для мониторинга набор рабочих инструкций и инструментов приходит с удалённого
MCP-сервера выбранного контура.

## Переключение между заявкой и мониторингом

Вы можете переключить режим в той же project-папке:

```sh
irraida mode switch --mode monitoring
irraida mode switch --mode application
```

Ключи заявки и мониторинга хранятся раздельно. Если для нового режима ключ ещё не
настроен, CLI попросит человека ввести его скрыто. После переключения перезапустите
агент: MCP-мост читает режим и ключ при запуске.

`irraida auth logout` удаляет только локальный ключ активного режима. Для отзыва
ключа в Flow или Monitoring используйте интерфейс соответствующей системы.

## Что делает установщик

Установщик кладёт исполняемый файл `irraida` в `~/.cargo/bin` и сохраняет receipt,
который нужен безопасному обновлению.

Чтобы команда находилась в новых терминалах, он добавляет одну строку в настройки
вашей оболочки — `.profile`, `.bashrc`, `.zshrc` или аналогичный файл:

```sh
. "$HOME/.cargo/env"
```

Больше ничего в систему не добавляется. Если удалите CLI, удалите и эту строку,
иначе оболочка будет сообщать об отсутствующем файле при каждом запуске.

## Обновление

```sh
irraida update check    # посмотреть, есть ли новая версия
irraida update apply    # установить обновление
```

CLI проверяет обновления не чаще раза в сутки. Проверка не блокирует работу и не
отправляет ключи, пути к вашим папкам или документы. Установка требует подтверждения;
если новая версия не запускается, CLI автоматически возвращает предыдущую.

## Если скачивали архив вручную

Если скачать `.tar.gz` или `.zip` браузером, macOS может пометить бинарь как
загруженный из интернета, и Gatekeeper откажется его запускать. Выберите один из
вариантов:

- в Finder щёлкните по файлу правой кнопкой и выберите «Открыть»;
- снимите пометку командой `xattr -d com.apple.quarantine irraida`.

Проще использовать установщик выше: он не создаёт этой проблемы.

## Безопасность

- Ключи хранятся только в Keychain на macOS, Credential Manager на Windows или
  Secret Service на Linux. Они не записываются в `.mcp.json`, `.cursor/mcp.json`,
  `AGENTS.md`, `CLAUDE.md` или state-файлы проекта.
- У заявки и мониторинга разные ключи и разные серверные контуры. Они не заменяют
  друг друга при переключении режима.
- Исходные документы и application custody исключены из Git. Не добавляйте ключи,
  документы или state-файлы в сторонние репозитории вручную.
- Файл версий подписан криптографически; CLI проверяет подпись перед обновлением.
